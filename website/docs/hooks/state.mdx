## useHash {/* #use-hash */}

<HashDemo />

```tsx
const [hash, setHash] = useHash();

const page = PAGES.some(p => p.key === hash) ? hash : PAGES[0].key;

setHash('settings'); // adds a history entry
setHash('settings', { replace: true }); // replaces the current one
```

`hash` is `location.hash` without the `#`, decoded, and `''` when there is
none (also on the server). Every component using the hook reads the same
value, including after back/forward.

## usePendingCommit {/* #use-pending-commit */}

<PendingCommitDemo />

```tsx
const pending = usePendingCommit<string, { code: string }>(document);

const latestDocument = () => pending.read()?.code ?? document;

const commit = (nextCode: string) => {
  pending.write({ code: nextCode });
  onChange(nextCode);
};
```

A write lasts until the end of the task it was made in (the event handler
and anything else in the same tick), or until the effects of the next commit
run if that comes first. `read()` also returns `undefined` as soon as a
render's `base` differs from the one the write was built on (`Object.is`),
so the render that receives the new value never reads a stale write. If the
parent rejects the change, by rendering with the same `base` or by not
rendering at all, the next event starts from `base` again. It can't tell a
rejection from a parent that applies the change later (`startTransition`, a
debounce), so the write is dropped for that too. The returned object keeps
its identity while `base` stays the same.

## useSet {/* #use-set */}

<SetDemo />

```tsx
const [collapsed, { toggle, set, clear }] = useSet<string>();

const isExpanded = (id: string) => !collapsed.has(id);

<button onClick={() => toggle(id)} />;
<button onClick={() => clear()}>Expand all</button>;
<button onClick={() => set(ids)}>Collapse all</button>;

// `delete` is a reserved word, so rename it when destructuring.
const [, { delete: remove }] = useSet<string>();
```

Every change produces a new `Set`, so the value works as a dependency and
with `memo`. An action that changes nothing, including `set` with the same
values, keeps the current `Set`. `toggle(value, true)` only adds and
`toggle(value, false)` only removes. The initial value is read on the first
render only, and the actions keep one identity for the life of the component.

## useMultiSelect {/* #use-multi-select */}

<MultiSelectDemo />

```tsx
const { selected, isSelected, toggle, clear } = useMultiSelect(items.length);
// shift-click range-select is mouse-only, so the modifier is captured on
// the CAPTURE phase (before Checkbox's own click-driven onChange fires)
// and read back in onChange, which fires exactly once per real toggle
// (mouse click or keyboard Space).
const shiftHeldRef = useRef(false);

<div
  onClickCapture={e => {
    shiftHeldRef.current = e.shiftKey;
  }}
>
  <Checkbox
    checked={isSelected(index)}
    onChange={() => toggle(index, shiftHeldRef.current)}
  >
    {item}
  </Checkbox>
</div>;
```
